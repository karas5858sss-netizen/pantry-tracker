# 📦 Pantry Tracker — Telegram Mini App

Telegram Mini App для домашнего учёта продуктов, запасов и сроков годности.

---

## 🚀 Статус проекта: Этап 8 (OCR распознавание даты)

Все основные этапы (0–8) успешно реализованы, протестированы (199 автоматических тестов, включая DB RLS smoke-test) и готовы к продуктивной эксплуатации.

### Реализованные этапы:
- **Этап 0:** Сканер штрихкодов на базе `zxing-wasm` с локальным WASM-модулем, режимы живого видеопотока, фото и ручного ввода EAN-13/EAN-8 с проверкой контрольных сумм GS1.
- **Этап 1:** Supabase RLS, серверная аутентификация по HMAC Telegram `initData`, белый список пользователей `allowed_users`, лимит на 10 пользователей, полная мультиязычность (`ru`, `es`, `en`).
- **Этап 2:** Склады и совместное использование: создание личных складов, генерация криптографических ссылок-приглашений (48 часов, 1 использование), переключатель складов, роли `owner` и `member`.
- **Этап 3:** Распознавание товаров: параллельный опрос баз Open Food Facts, Open Products Facts, Open Beauty Facts и UPCitemdb с автоматическим кэшированием в каталог и возможностью ручного ввода/редактирования.
- **Этап 4:** Ввод сроков годности: быстрые пресеты (+3 дня, +7 дней, +1 месяц, +6 месяцев), точный календарный ввод, режим конца месяца (ММ/ГГГГ с авто-определением последнего дня), валидация диапазона дат.
- **Этап 5:** Управление запасами и списание:
  - Главный экран со вкладками «📦 Склад» и «📷 Сканер».
  - Живой поиск по названию и штрихкоду, FIFO-сортировка (ранний срок годности вверху).
  - Светофорные бейджи свежести: 🔴 просрочено, 🟡 ≤3 дней (сегодня/скоро), 🟢 свежее.
  - Автоматическое объединение одинаковых партий при добавлении (увеличение количества вместо дублирования).
  - Управление количеством прямо в карточке товара: степпер `[ − ] qty [ + ]` и прямой ввод точного числа.
  - Быстрое удаление всей позиции через иконку 🗑️ и полная очистка склада кнопкой «Очистить всё».
  - Списание сканированием: переключатель режимов «+ Приход» vs «− Списание» с автоматическим выбором партии по FIFO или выбором вручную при нескольких партиях.
  - Баннер отмены (Undo) с 5-секундным таймером.
- **Этап 6:** Фоновые напоминания в Telegram:
  - Серверная Edge Function `send-reminders`, защищённая токеном `CRON_SECRET`.
  - Учёт часовых поясов пользователей (включая `Europe/Moscow`, `Europe/Madrid` и др.) с проверкой наступления часа напоминания.
  - Градация стадий: Стадия 1 (1–2 дня), Стадия 2 (сегодня), Стадия 3 (просрочено до 7 дней назад).
  - Дедупликация через таблицу `reminder_log(user_id, item_id, stage)`: ни одно уведомление не дублируется.
  - Группировка: ровно 1 сообщение на склад в формате Telegram HTML с экранированием тегов и ограничением до 20 позиций.
  - Обработка 403 Forbidden от Telegram с авто-отзывом доступа `can_write_pm = false`.
  - Модальное окно настроек пользователя ⚙️ в приложении: включение/отключение уведомлений, выбор часа (00:00..23:00) и часового пояса.
- **Этап 7:** Сборка, деплой и приёмка:
  - Настроенный CI/CD пайплайн на GitHub Actions:
    - Джоба `validate`: проверка типов (`npm run check`) -> unit-тесты (`npm test`) -> сборка фронтенда (`npm run build`).
    - Джоба `db-smoke`: подъём локального Supabase (`supabase start`), накат миграций и запуск DB smoke-теста (`npm run test:smoke`), подтверждающего блокировку прямого доступа и обхода RLS через публичный `anon` ключ на всех 8 таблицах.
  - Полная защита секретов (клиент не содержит токенов, ключей service_role и секретов cron).
  - Готовые инструкции для деплоя на Cloudflare Pages и подключения к `@BotFather`.
  - Чек-лист приемочного тестирования на смартфонах.
- **Этап 8 (Опционально):** Клиентский OCR даты срока годности:
  - Интеграция `tesseract.js` с полным локальным размещением всех ассетов (`/public/tesseract/`: worker, core wasm, traineddata) — **нулевая зависимость от внешних CDN**.
  - Предобработка изображения: кадрирование по рамке видоискателя, преобразование в оттенки серого, контрастирование для распознавания точечных/струйных штампов на упаковках.
  - Поддержка форматов: `DD.MM.YYYY`, `DD.MM.YY`, `MM.YYYY` (с привязкой к последнему дню месяца), текстовые месяцы (на английском, испанском и русском языках, напр. `12 OCT 2026`, `15 ENE 2027`, `15 ОКТ 2026`).
  - Фильтрация валидных дат: автоматический отсев дат за пределами `[сегодня − 1 год … сегодня + 10 лет]`.
  - Экран подтверждения: отображение списка найденных кандидатов с бейджами формата, пользователь выбирает нужную дату и явно нажимает кнопку подтверждения (**никакого автосохранения**).
  - Кнопка вызова `📷 Скан даты` в карточке добавления товара.

## 🛠️ Локальный запуск и разработка

### Требования
- Node.js 20+ (рекомендуется Node.js 22 LTS)
- npm 10+

```bash
npm ci
```

```bash
npm test
```

```bash
npm run test:watch
```


```bash

```

## 🔒 Переменные окружения

### 1. Клиентская часть (Frontend / Cloudflare Pages / `.env.local`):
Только публичные параметры, безопасные для клиента:
```ini
VITE_SUPABASE_URL=https://hvyotkemriptfbeeczlu.supabase.co
VITE_SUPABASE_ANON_KEY=sbp_...
VITE_TELEGRAM_BOT_NAME=pantry_tracker_bot
```

### 2. Серверная часть (Supabase Edge Functions):
Секреты задаются через `supabase secrets set` или в панели Supabase Dashboard:
- `BOT_TOKEN` — токен Telegram-бота от `@BotFather`
- `CRON_SECRET` — секретная строка для вызова cron worker `send-reminders`
- `SUPABASE_URL` — системная переменная проекта Supabase
- `SUPABASE_SERVICE_ROLE_KEY` — системный сервисный ключ для доступа к базе в обход клиентских ограничений

Секреты **никогда** не попадают в исходный код и git.

## 🌐 Деплой на Cloudflare Pages

### Вариант 1: Автоматический деплой через Git (Рекомендуется)

1. Зайдите в [Cloudflare Dashboard](https://dash.cloudflare.com/) → **Workers & Pages** → **Create application** → **Pages** → **Connect to Git**.
2. Выберите ваш репозиторий `pantry-tracker`.
3. Укажите параметры сборки:
   - **Framework preset:** `Vite` (или `None`)
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
4. В разделе **Environment variables (Production)** добавьте:
   - `NODE_VERSION` = `22`
   - `VITE_SUPABASE_URL` = `https://<PROJECT_REF>.supabase.co`
   - `VITE_SUPABASE_ANON_KEY` = `<YOUR_ANON_KEY>`
   - `VITE_TELEGRAM_BOT_NAME` = `<YOUR_BOT_USERNAME>`
5. Нажмите **Save and Deploy**.
6. Cloudflare скомпилирует проект и выдаст адрес вида `https://<project-name>.pages.dev`.

### Вариант 2: Деплой через Wrangler CLI
```bash
npm run build
npx wrangler pages deploy dist --project-name pantry-tracker
```

1. Откройте диалог с [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте команду `/newapp`.
3. Выберите вашего бота.
4. Введите название: `Pantry Tracker`.
5. Введите описание: `Учёт продуктов и сроков годности`.
6. Загрузите иконку (640x360 px) или введите `/empty`.
7. В поле **Web App URL** укажите URL из Cloudflare Pages:
   ```
   https://<project-name>.pages.dev
   ```

8. Введите short name (например, `app`).

## ⏰ Настройка расписания напоминаний (Cron)

Эндпоинт `send-reminders` запускается ежечасно (например, через `pg_cron` в Supabase или внешний планировщик GitHub Actions / Cloudflare Cron / cron-job.org):

```bash
curl -X POST "https://<PROJECT_REF>.supabase.co/functions/v1/send-reminders" \
  -H "Authorization: Bearer <CRON_SECRET>"
```

Внутри Supabase SQL Editor для ежечасного запуска через `pg_cron`:
```sql
select cron.schedule(
  'pantry-hourly-reminders',
  '0 * * * *',
  $$
  select
    net.http_post(
      url := 'https://<PROJECT_REF>.supabase.co/functions/v1/send-reminders',
      headers := jsonb_build_object(
        'Content-Type', 'application/json',
        'Authorization', 'Bearer <CRON_SECRET>'
      )
    ) as request_id;
  $$
);
```

## 📱 Чек-лист приёмочного тестирования (Этап 7)

Проверьте приложение внутри Telegram по ссылке `https://t.me/<BOT_USERNAME>/app` на физических смартфонах:

### 1. Мобильные платформы (iOS и Android):
- [ ] **iOS (iPhone Safari WebApp):**
  - При первом открытии сканера всплывает системный запрос на доступ к камере.
  - Видеопоток запускается мгновенно без чёрного экрана.
  - Работает тактильный отклик (Haptic Feedback) при сканировании и действиях.
- [ ] **Android (Chrome WebApp):**
  - Камера запускается корректно.
  - Поворот и изменение размера окна Telegram обрабатываются без сбоев.

### 2. Темы Telegram:
- [ ] При переключении темы Telegram (светлая / тёмная) цвета фона, карточек, текста и кнопок мгновенно адаптируются через системные переменные темы Telegram.

### 3. Распознавание товаров (RU и ES супермаркеты):
- [ ] **Товар из магазина РФ:** отсканируйте штрихкод (например, молоко, чай) — товар распознаётся через базы OFF/каталог, подставляется русское наименование.
- [ ] **Товар из испанского магазина:** отсканируйте европейский/испанский штрихкод (например, сок или оливки Mercadona/Carrefour, код с префиксом `84...`) — распознаётся наименование товара.

### 4. Совместное использование (Sharing):
- [ ] Владелец склада нажимает «🔗 Пригласить» и отправляет ссылку второму Telegram-пользователю.
- [ ] Второй пользователь переходит по ссылке:
  - Успешно добавляется в склад с ролью «Участник».
  - Видит все актуальные товары склада.
  - Изменения, внесённые одним пользователем (списание, изменение количества, добавление), синхронизируются.
- [ ] Повторный переход по той же ссылке третьим пользователем отклоняется (одноразовое приглашение).

### 5. Напоминания и часовые пояса:
- [ ] В меню настроек ⚙️ выберите удобный час (например, текущий час) и часовой пояс (`Europe/Moscow` или `Europe/Madrid`).
- [ ] При наступлении этого часа пользователь получает ровно **одно** сгруппированное сообщение на каждый склад со списком истекающих товаров в Telegram.
- [ ] Повторное напоминание по той же позиции в рамках той же стадии не приходит (дедупликация в `reminder_log`).

### 6. Безопасность и RLS:
- [ ] Попытка открыть приложение с поддельным или просроченным `initData` завершается ошибкой 401 с понятным сообщением.
- [ ] Прямой запрос к таблицам Supabase с публичным `anon` ключом в обход Edge Functions блокируется (Row Level Security включен на всех таблицах с 0 клиентскими политиками).
